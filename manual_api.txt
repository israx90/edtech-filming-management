MANUAL DE INTEGRACIÓN - API DE CONSULTA DE DISPONIBILIDAD
=========================================================

Este documento explica cómo interpretar la respuesta JSON de la API de Consulta de Disponibilidad de la plataforma de filmación.

---

CÓMO USAR LA API
----------------

**Endpoint base:** `https://calendario.unifranz.online`

**Disponibilidad Mensual:**
`GET /api/query/availability?year=2026&month=7`

**Disponibilidad por Rango:**
`GET /api/query/availability/range?start_date=2026-07-01&end_date=2026-07-31`

**Un Día Específico:**
`GET /api/query/availability/2026-07-15`

**Autenticación (header HTTP):**
`Authorization: Bearer 4a91b20dd62bb6e5835b9a521cb45f06a0008a9173a8efad6be143fa8de9d6b1de555c1da9088d69`

---

ESTRUCTURA GENERAL DEL JSON
--------------------------

El JSON devuelto contiene 5 secciones principales en su raíz:

1. "year" (Número): El año consultado (ej. 2026).
2. "month" (Número): El mes consultado (ej. 7 para Julio).
3. "studio_hours" (Objeto): El horario oficial de funcionamiento del estudio.
   - "start" (Texto): Hora de apertura (ej. "08:00").
   - "end" (Texto): Hora de cierre (ej. "18:00").
4. "work_days" (Array): Días laborales de la semana (1 = Lunes, 5 = Viernes. El fin de semana es Sábado y Domingo).
5. "total_days" (Número): Cantidad de días que tiene el mes (ej. 31).
6. "summary" (Objeto): Resumen estadístico mensual del estado de los días.
   - "available": Días que están 100% disponibles.
   - "partial": Días que tienen algunas horas ocupadas, pero tienen otras horas libres.
   - "occupied": Días que están 100% ocupados (sin horas libres).
   - "displacement": Días que tienen un "Desplazamiento de Equipo" (en este estado, el estudio se reporta como 100% libre).
   - "closed": Días cerrados (fines de semana, feriados o días no laborables).
7. "availability" (Array): La lista detallada día por día del mes.

---

CÓMO INTERPRETAR LA LISTA DE DETALLE ("availability")
------------------------------------------------------

Cada elemento dentro de la lista representa un día específico y contiene los siguientes campos según su estado:

### Caso 1: Día con Disponibilidad Parcial ("status": "partial")
Significa que el estudio está ocupado en algunos horarios, pero tiene bloques de tiempo disponibles.
*Ejemplo:*
```json
{
  "date": "2026-07-01",
  "status": "partial",
  "is_displacement": false,
  "free_slots": [
    {"start": "08:00", "end": "09:00"},
    {"start": "12:00", "end": "14:00"},
    {"start": "17:00", "end": "18:00"}
  ]
}
```
* **Interpretación:** En este día, el estudio solo puede ser reservado en los siguientes rangos horarios libres ("free_slots"):
  - De 08:00 a 09:00 (1 hora disponible).
  - De 12:00 a 14:00 (2 horas disponibles).
  - De 17:00 a 18:00 (1 hora disponible).
  Cualquier hora fuera de estos rangos está ocupada por otra filmación.

### Caso 2: Día Completamente Disponible ("status": "available")
Significa que el estudio no tiene ninguna reserva para este día.
*Ejemplo:*
```json
{
  "date": "2026-07-04",
  "status": "available",
  "is_displacement": false,
  "free_slots": [
    {"start": "08:00", "end": "18:00"}
  ]
}
```
* **Interpretación:** El día completo está libre. Se puede agendar cualquier filmación dentro del horario del estudio (de 08:00 a 18:00).

### Caso 3: Día Cerrado o No Laborable ("status": "closed")
Significa que el estudio no atiende ese día (fines de semana, feriados oficiales configurados por el administrador, o días especiales de mantenimiento).
*Ejemplo:*
```json
{
  "date": "2026-07-05",
  "status": "closed",
  "reason": "Día no laborable"
}
```
* **Interpretación:** No se pueden agendar filmaciones. El campo `"reason"` explica el porqué (ej. "Día no laborable" para fines de semana, o el nombre del feriado correspondiente).

### Caso 4: Día con Desplazamiento de Equipo ("status": "displacement")
Un caso especial donde se registró que el equipo de filmación se desplaza fuera del estudio.
*Ejemplo:*
```json
{
  "date": "2026-07-15",
  "status": "displacement",
  "is_displacement": true,
  "free_slots": [
    {"start": "08:00", "end": "18:00"}
  ]
}
```
* **Interpretación:** Aunque haya un registro en el calendario para este día, el estado es "displacement" (desplazamiento), lo que significa que el estudio físico queda 100% disponible (de 08:00 a 18:00) para que otro sistema lo reserve si lo necesita.

---

RECOMENDACIONES PARA EL DESARROLLADOR DEL OTRO SISTEMA
------------------------------------------------------

1. **Mostrar Visualmente:**
   - Dibuja un calendario mensual en tu aplicación.
   - Pinta de **Verde** los días con `"status": "available"` o `"status": "displacement"`.
   - Pinta de **Amarillo / Naranja** los días con `"status": "partial"`. Al hacer clic en ellos, muestra al usuario la lista de `"free_slots"` para que elija una de las horas permitidas.
   - Pinta de **Gris / Rojo** los días con `"status": "closed"` o `"status": "occupied"` y no permitas hacer reservas sobre ellos.

2. **Validar antes de Reservar:**
   - Cuando el usuario elija una fecha y hora, comprueba que la hora seleccionada esté contenida dentro de los bloques descritos en `"free_slots"` para ese día en el JSON.

NUEVO ENDPOINT: CONSULTA DE HORARIOS DE STAFF
---------------------------------------------

El API que acabo de crear es `/api/query/staff-schedule`.

Para integrarlo en tu otro sistema y consultar qué días tiene grabación Rubi, debes hacer una petición HTTP GET. Dado que es un endpoint de consulta externo, requiere la API Key del sistema (puedes enviarla en la cabecera Authorization o en la URL).

Aquí tienes un ejemplo práctico de cómo integrarlo usando JavaScript (con fetch):

```javascript
async function consultarHorariosStaff(nombreStaff) {
  // Construyes la URL. Agregamos staff_name=rubi
  // Opcional: puedes agregar &year=2026&month=7 para buscar por mes, 
  // o &start_date=2026-07-01&end_date=2026-07-31 para buscar por rango.
  const url = `/api/query/staff-schedule?staff_name=${nombreStaff}`;
  
  // Tu API KEY de acceso a la plataforma (la que se genera desde los Ajustes del sistema)
  const API_KEY = "TU_API_KEY_SECRETA_AQUI";
  try {
    const respuesta = await fetch(url, {
      method: 'GET',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${API_KEY}` // Mandamos la llave de acceso
      }
    });
    if (!respuesta.ok) {
      throw new Error(`Error HTTP: ${respuesta.status}`);
    }
    const datos = await respuesta.json();
    
    // Aquí puedes ver los resultados
    console.log(`Encontradas ${datos.count} filmaciones para ${nombreStaff}`);
    
    // Recorrer la lista de días para mostrarlos en pantalla
    datos.schedule.forEach(sesion => {
      console.log(`- Día: ${sesion.date}`);
      console.log(`- Horario: ${sesion.start_time} a ${sesion.end_time}`);
      console.log(`- Asignados: ${sesion.assigned_staff.join(', ')}`);
      console.log(`- Materia: ${sesion.details.subject}`);
      console.log('---');
    });
    return datos.schedule;
    
  } catch (error) {
    console.error("Error al consultar el horario del staff:", error);
  }
}
// Para ejecutar la consulta:
consultarHorariosStaff("rubi");
```

### Otra forma de integrarlo (con `?api_key`)
Si el sistema que estás usando no te permite enviar cabeceras HTTP (Headers), también puedes enviar la llave directamente en la URL así:

`https://tudominio.com/api/query/staff-schedule?staff_name=rubi&api_key=TU_API_KEY_SECRETA_AQUI`

Una vez que tengas la respuesta, el campo principal que te interesa procesar para dibujar la UI es el array `datos.schedule`, que contiene la lista exacta de las sesiones donde ese staff está asignado.
